# Сергей Водопетов — персональный сайт

Исходники актуальной версии сайта: главная, PR, Digital, наука и образование, жизненные интересы, «О Сергее» и биография с источниками. Включены портрет, четыре фотографии, монохромные и цветные логотипы, мобильная верстка, SEO и браузерный редактор `/edit/`.

## Стек

| Слой | Реализация |
| --- | --- |
| Приложение | Next.js 16.4.6, App Router, серверный рендеринг |
| Интерфейс | React 19.2.6, TypeScript, обычный CSS без UI-фреймворка |
| Редактор | TipTap 3: заголовки, абзацы, выделение, списки, цитаты, ссылки |
| Обработка текста | Очистка HTML на сервере через sanitize-html |
| Данные | Один JSON-документ; на VPS — постоянный каталог на диске; в Sites — Cloudflare R2 |
| Вход в редактор | На VPS — пароль и подписанная HttpOnly cookie; в Sites — вход владельца через ChatGPT |
| Изображения | Локальные PNG/SVG/WebP, несколько размеров фотографий |
| Шрифты | Golos Text и Unbounded, локально через Fontsource, лицензии SIL OFL |
| SEO | Метаданные страниц, canonical, Open Graph, Person/ProfilePage JSON-LD, sitemap.xml, robots.txt |
| Размещение | VPS с Node.js либо Cloudflare Workers через OpenNext 1.20.16 |

Отдельная CMS, PostgreSQL, Redis и платные сервисы для работы на VPS не нужны. Рекомендуется один процесс приложения и один сервер: дисковые записи сериализуются внутри процесса. Для нескольких реплик нужен общий backend хранения с межпроцессной блокировкой.

## Развёртывание на VPS

Подробная пошаговая инструкция: **[docs/VPS.md](docs/VPS.md)**. Готовые шаблоны: [systemd](deploy/site-sv.service) и [Nginx](deploy/nginx.conf).

Практический ориентир: Linux, Node.js 24 LTS, Nginx, домен с HTTPS, 1–2 vCPU и 2 ГБ RAM для небольшого сайта. Для сборки удобнее 4 ГБ RAM или swap; это ориентир, а не результат нагрузочного теста. Для файлов приложения и зависимостей оставьте несколько гигабайт свободного места.

Короткий запуск после установки Node.js:

```bash
git clone https://github.com/voodoo2serg/site_sv.git
cd site_sv
npm ci
cp .env.example .env.local
# Заполните .env.local: адрес сайта, пароль и CONTENT_DIRECTORY.
npm run check
npm test
npm run build:vps
npm run start:vps
```

`start:vps` слушает `127.0.0.1:3000`; снаружи подключается Nginx. В production используйте HTTPS: cookie редактора имеет флаг Secure. Пароль — уникальная случайная строка минимум из 24 символов. Не помещайте пароль в git.

Важно: `npm run build` сохранён для первоначального Cloudflare/Sites-хостинга. **Для VPS используйте `npm run build:vps`.**

## Как править тексты

### Через браузер — основной способ

1. Откройте `https://ваш-домен/edit/`.
2. На VPS введите пароль `EDITOR_PASSWORD`; на текущем закрытом Sites-сайте вход обеспечивает ChatGPT.
3. Выберите страницу, измените текст и его форматирование. Можно править SEO-поля, почту, подписи логотипов и внешние ссылки.
4. Нажмите **«Сохранить»**. Страницы обновятся без пересборки и перезапуска.
5. **«Скачать копию»** выгружает JSON с текущими текстами. **«Загрузить копию»** импортирует его в редактор; для публикации затем нужно нажать «Сохранить».

Фотографии, логотипы, набор страниц и CSS редактор не меняет. Биография намеренно отсутствует в основном меню; ссылка на неё находится внизу страницы «О Сергее».

### Через файлы

- `data/content.json` — исходные тексты из репозитория.
- `$CONTENT_DIRECTORY/content.json` — тексты, сохранённые на VPS через редактор; они имеют приоритет над исходными.
- `$CONTENT_DIRECTORY/previous.json` — предыдущая сохранённая версия.

Правка `data/content.json` требует пересборки. Если существует сохранённый `content.json`, изменение исходного файла не заменяет его: используйте редактор или импорт JSON. Перед ручным изменением рабочего JSON остановите сервис и сделайте копию каталога; сохраните структуру, увеличьте `version` и измените `updatedAt`.

`contentRevision` — номер редакционной миграции. Не удаляйте и не уменьшайте его: иначе повторно применятся старые редакционные правки из `lib/editorial.ts`. Обычное изменение текста не требует менять `contentRevision`.

## Постоянное хранение и резервные копии

На VPS задайте, например, `CONTENT_DIRECTORY=/var/lib/site-sv`. Каталог должен быть вне git-каталога приложения, доступен на запись пользователю сервиса и находиться на постоянном диске. При первом сохранении он создаётся, если родительский каталог доступен на запись.

Переустановка кода не удаляет эти тексты. Резервируйте весь каталог; `previous.json` хранит только одну предыдущую версию и не заменяет регулярные резервные копии. До переноса с Sites скачайте актуальный JSON через редактор, а после запуска VPS загрузите его там.

Без `CONTENT_DIRECTORY` production-версия Node.js показывает исходные тексты, но отказывает в сохранении. В режиме разработки используется `.local-data/`. В Sites применяется R2 `BUCKET`: `site/content.json`, `site/previous.json`, `site/owner.json`.

## Команды

```bash
npm run dev         # локальная разработка
npm run check       # TypeScript
npm test            # авторизация, очистка HTML, хранение и конфликт версий
npm run build:vps   # сборка для Node.js / VPS
npm run start:vps   # Node.js на 127.0.0.1:3000
npm run test:vps    # production smoke test; предварительно build:vps
npm run build       # сборка Cloudflare/OpenNext для первоначального хостинга
```

Production smoke test запускает временный сервер на loopback, проверяет вход, сохранение и чтение после перезапуска. Используется отдельный временный каталог; рабочие тексты не затрагиваются.

## Структура

- `app/` — маршруты и API сохранения/входа.
- `components/` — верстка, логотипы и браузерный редактор.
- `lib/` — данные, авторизация и редакционные миграции.
- `data/` — исходные тексты и происхождение логотипов.
- `public/assets/` — фотографии и знаки; `public/licenses/` — лицензии шрифтов.
- `deploy/`, `docs/` — инструкции и конфигурация VPS.

## Первоначальный Sites-хостинг

`.openai/hosting.json`, `wrangler.jsonc`, `open-next.config.ts` и `scripts/package-worker.mjs` относятся к текущему Sites/Cloudflare-размещению; на VPS они не используются. Доступ на существующем сайте этим экспортом не меняется.

В Sites первый разрешённый вход владельца закрепляет его site-scoped ID в R2. Инициализация разрешена при `OWNER_PRIVATE_EDITOR=true` только на owner-private сайте. После первого входа отключите этот флаг перед расширением доступа; не удаляйте `site/owner.json`. На VPS оставьте этот параметр пустым и используйте пароль. Не доверяйте identity-заголовкам, присланным посетителем; пример Nginx их удаляет.

## Ресурсы

Происхождение официальных логотипов: `data/logo-sources.json`. Знак СТС предоставлен владельцем и используется в контексте работы в СТС Медиа. У авторских продуктов без фирменного знака — текстовые названия. В покое логотипы монохромные, при наведении и фокусе — оригинальные цвета. Логотипы организаций не передаются под лицензией шрифтов.

Аналитика, рекламные трекеры и формы сбора контактов не подключены. Контакт открывается через mailto. Техническая обработка запросов хостингом описана на сайте отдельно.
